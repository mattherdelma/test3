# Building & running on Windows 10 with Visual Studio 2019

There are two ways to build, depending on whether you want the GPU pipeline.

| | What it builds | Dependencies | How |
|---|---|---|---|
| **A. Native solution** | tracking library + portable unit tests | Eigen only | open `vs2019\RTPercept.sln` |
| **B. CMake pipeline** | everything incl. DXGI + YOLOv8/TensorRT | CUDA, TensorRT, Eigen | `scripts\generate_vs2019.bat pipeline` |

Toolset: **v142** (VS2019), platform **x64**, language standard **C++17**.

---

## A. Native VS2019 solution (no CUDA) — runs out of the box

This is the fastest way to compile and run the verifiable parts (Kalman filter,
ByteTrack association, lock-free queue).

1. **Get Eigen** (header-only). Either:
   - download Eigen 3.4 and point an env var at it:
     ```bat
     setx EIGEN3_INCLUDE_DIR C:\libs\eigen-3.4.0
     ```
   - or `vcpkg install eigen3:x64-windows` (the projects also probe
     `%VCPKG_ROOT%\installed\x64-windows\include\eigen3`).
2. Open `vs2019\RTPercept.sln` in Visual Studio 2019.
3. Select **Release | x64**.
4. Build the solution (Ctrl+Shift+B).
5. Run the tests:
   - Set **RTPercept.TestTracking** as the startup project → Ctrl+F5.
   - Set **RTPercept.TestSpscQueue** as the startup project → Ctrl+F5.

Both print their results and return exit code 0 on success.

The solution contains three projects:

- `RTPercept.Tracking` — static library (`KalmanFilter`, `STrack`,
  `LinearAssignment`, `BYTETracker`).
- `RTPercept.TestTracking` — unit tests for the tracker (links the library).
- `RTPercept.TestSpscQueue` — multithreaded test for the lock-free queue.

The Eigen include path is resolved once in `vs2019\RTPercept.Common.props`.

---

## B. Full CUDA / TensorRT / DXGI pipeline

This builds `rtpercept.exe` (the live capture→detect→track app) plus the DXGI
capture smoke test. It needs an NVIDIA GPU (you have an RTX 4060 Ti, sm_89).

### Prerequisites

1. **Visual Studio 2019** with the *Desktop development with C++* workload
   (includes the Windows 10 SDK → D3D11/DXGI headers and libs).
2. **CUDA Toolkit 12.x** — install with the *Visual Studio integration*
   component so MSBuild knows how to compile `.cu` files.
3. **TensorRT 8.6 or 10.x** for Windows. Set:
   ```bat
   set TENSORRT_ROOT=C:\TensorRT-10.x
   ```
4. **Eigen** as in section A (`EIGEN3_INCLUDE_DIR`).

### Generate and build

```bat
scripts\generate_vs2019.bat pipeline
cmake --build build\vs2019-pipeline --config Release
```

Open `build\vs2019-pipeline\rtpercept.sln` in VS2019 if you prefer the IDE. The
CUDA target architecture is set to **sm_89** (Ada / RTX 40-series) in
`CMakeLists.txt`.

### Export a YOLOv8 engine

```bat
yolo export model=yolov8s.pt format=onnx opset=12 imgsz=640
trtexec --onnx=yolov8s.onnx --saveEngine=yolov8s.fp16.engine --fp16
```

### Run

```bat
build\vs2019-pipeline\Release\rtpercept.exe yolov8s.fp16.engine
```

Press **Ctrl+C** to stop. It prints rolling stats: detections, active tracks,
inference time, end-to-end latency, FPS, and dropped frames.

### Notes / gotchas

- **`NOMINMAX`** and **`WIN32_LEAN_AND_MEAN`** are defined globally — without
  `NOMINMAX`, `<windows.h>`'s `min`/`max` macros break `std::min`/`std::max`
  and Eigen. Keep them.
- DXGI Desktop Duplication does **not** capture across a standard Remote
  Desktop session the same way it does on a local console; test on the
  physical machine or a session that exposes a GPU output.
- If `trtexec`/TensorRT version differs from the headers you build against,
  regenerate the engine — engines are not portable across major TRT versions.
